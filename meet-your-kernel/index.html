A visual guide for the curious

The kernel is the one program that's allowed to touch the hardware.

Every app on your phone or laptop is locked out of the chips it runs on. When an app wants to read a file, play a sound, or light up a pixel, it has to ask the kernel to do it. You make that request thousands of times a second without noticing.

    What the kernel does all day

    A computer has one set of hardware and dozens of programs that all want it at once. The kernel is the referee. Its work comes down to four jobs.

    Sharing the CPU

    The scheduler decides which program runs right now and for how long, then swaps in the next one. Each turn lasts a few milliseconds.

    Handing out memory

    Each program gets its own private slice of RAM. One app cannot read or scribble over another's, which is why a crashed app rarely takes the whole machine with it.

    Talking to devices

    Drivers are the kernel's translators. Each one knows the exact electrical language of one chip: a Wi-Fi radio, a touchscreen, a camera sensor.

    Organizing files and networks

    A drive only stores numbered blocks, and a network only carries packets. The kernel turns those into folders, files and connections that apps can use.

    Try it: one CPU core, four apps

    A single core can run only one program at a time. Start slow to see the kernel pass the CPU around, then drag the slider right. Past about 30 switches a second your eye can no longer tell that anyone is waiting. A real kernel switches faster than that.

    Linux, and the Linus behind it

    The name you heard is Linux. It was started in 1991 by a Finnish student, Linus Torvalds, who wanted a free operating system for his own PC. The name blends "Linus" with "Unix", so typing "linus" was closer than you might think.

    Strictly speaking, Linux is only the kernel. Ubuntu, Fedora and Android are complete systems built around it. Anyone can read its source code, which makes it the best kernel to learn from.

    Say hello to your own kernel

    Open a terminal (Terminal on Mac or Linux, Command Prompt on Windows) and type one of these. Each takes about ten seconds and changes nothing on your machine.

    uname -sr

    Mac and Linux. Prints your kernel's name and version. A Mac answers Darwin, the system XNU belongs to.

    ver

    Windows. Prints the Windows version, which carries the NT kernel's version number.

    top

    Mac and Linux. A live list of every program the scheduler is juggling. Press q to leave.

    strace -c ls

    Linux only. Counts every system call the tiny ls command makes. Listing one folder takes dozens of requests to the kernel.

    Where electrical engineering meets the kernel

    The kernel is where software ends and circuits begin, which makes it a good place for your interests to meet. Three ways in, from easiest to deepest:

    Run a kernel yourself

    A Raspberry Pi is a small Linux computer with exposed pins. Blinking an LED from it means asking the kernel to change a voltage for you.

    Then run without one

    Do the same blink on an Arduino, which has no kernel. Comparing the two teaches what a kernel adds and what it costs.

    Learn the vocabulary

    Interrupts, drivers and memory addressing are the ideas shared by both fields. A first course in digital logic or computer architecture covers all three.
